# 校园集市全站 UI/UX 审计报告

## 概述
本报告对“校园集市”平台（包含二手交易、跑腿大厅、技能服务、物品租赁、消息中心、个人中心、信任认证及管理后台）全站页面进行了深入的 UI/UX 审计。

---

## 1. 全局共性问题汇总

### 1.1 布局与尺寸失衡
- **内容宽度不统一**：全站页面容器最大宽度随意使用 `max-w-4xl`、`max-w-5xl`、`max-w-6xl`、`max-w-7xl`，无统一设计标准。
- **左右比例严重失衡**：在详情页（如 `/products/[id]`、`/rentals/[id]`）中，右侧操作栏因平铺嵌套了发起购买、举报等多个大型 Form，导致右侧极长、左侧主图短，产生大量无意义空白。
- **缺乏弹性设计**：在 1440px+ 大屏上，表单输入框全屏拉满（单行长度超过 1000px），严重损害阅读体验与填写效率。

### 1.2 卡片过度嵌套与视觉噪声
- **“卡片套卡片”现象严重**：页面主体是 Rounded Card，内部卖家信息又是 Rounded Card，表单项外层又套一层 Card。
- **边框与阴影滥用**：几乎每个 `div` 都带 `border border-slate-200` 和 `shadow-sm`，导致视觉层级不清、噪声极大。
- **圆角不统一**：同一页面混合出现 `rounded-xl`、`rounded-2xl`、`rounded-3xl`、`rounded-[28px]`、`rounded-[32px]` 和 `rounded-full`，缺乏严谨的 Design Tokens。

### 1.3 低频功能默认全展开
- **高低频不分**：如商品/租赁/技能详情页中，“举报表单”、“购买表单”等低频/触发式交互默认占据页面大面积版面，且举报区常带有大面积黄色或红底警告色，干扰核心交易主流程。
- **操作按钮混淆**：“我的订单”等导航性质按钮被错误放置在商品购买操作区中。

### 1.4 字体与颜色层级模糊
- **字号阶梯乱**：标题与正文对比度不足（例如 24px 与 18px 混用），主标题与副标题缺乏规范的 font-weight 和 leading。
- **颜色体系混乱**：使用了过多的 Slate/Indigo/Blue/Rose/Amber 色值，缺乏系统性的 Primary、Secondary、Muted、Destructive 色阶规范。

### 1.5 移动端体验不合格
- **缺失 Mobile 专属布局**：桌面端两栏布局在移动端仅简单 flex-col 堆叠，底部缺少 Sticky 移动端操作栏（Mobile Action Bar）。
- **点击区域过小**：部分关闭、图标按钮尺寸低于 44px * 44px 触控标准。

## 2. 重点页面审计细节

| 页面 | 主要问题 | 布局/间距问题 | 交互与组件问题 | 改进方案 & 优先级 |
|---|---|---|---|---|
| **首页 `/`** | 业务板块堆叠感强，Hero 区与列表过渡生硬 | 间距不一致（部分 24px 部分 64px） | 缺乏统一的服务/商品Card视觉 | 重新设计 Hero 视觉，统一四类业务入口与推荐网格 **[P0]** |
| **商品详情 `/products/[id]`** | 购买表单与举报表单默认全展开，高度严重失衡 | `grid-cols-[1fr_0.9fr]` 右侧极长，下部大空白 | 卖家信息仅纯文本堆叠，“我的订单”错置 | 采用 55%:45% sticky 布局，购买改 Drawer/Dialog，举报改 Dialog **[P0]** |
| **商品列表 `/products`** | 筛选栏居中与网格不匹配，卡片风格散乱 | 过滤器 padding 混乱 | 商品卡片无统一标签与规范价格 | 统一 PageHeader + Standard FilterBar + Responsive Grid **[P1]** |
| **发布/编辑商品 `/products/new`** | 输入框在桌面端无限横向拉满 | 单栏平铺，字段无语义化分组 | 缺少 FormSection 分组与明确的提交操作区 | 表单限制 `max-w-3xl`，分组卡片化（图片/基本/价格/交易） **[P1]** |
| **跑腿大厅 `/errands`** | 悬赏金额与任务类型标签层级不明 | 卡片外框过重，元素紧贴 | 缺少极简 StatusBadge 和规范发单入口 | 重新设计 ErrandCard，突出悬赏与急件标记，优化列表 **[P1]** |
| **跑腿详情 `/errands/[id]`** | 抢单/接单与完成确认按钮无明晰状态转换 | 单栏布局缺乏重点 | 状态日志与接单人信息排版混乱 | 采用左侧任务详情、右侧接单卡片结构 **[P1]** |
| **技能服务广场 `/services`** | 服务卡片像普通博客文章，无服务感 | 缺少服务定价单位与服务时间展示 | 预约表单平铺 | 重构 ServiceCard，增加评分、服务范围与简易预约面板 **[P1]** |
| **租赁广场 `/rentals`** | 租金单位（/天、/周）展示规则不统一 | 筛选条项数过多挤压页面 | 缺少免押金标签的视觉提亮 | 规范价格单位 Display，增强筛选 FilterBar 抽屉 **[P1]** |
| **租赁详情 `/rentals/[id]`** | 租赁规则、押金政策、表单四处堆叠 | 页面超过 3 屏，核心预约面板被推挤 | 预约与算价器平铺在右侧 | 右侧使用 Sticky 动态算价预约面板，详情下置 **[P1]** |
| **个人主页 `/users/[id]`** | 个人数据展示干瘪，发布历史与评价直接平铺 | 头部缺乏 Banner 和规范 UserSummaryCard | 缺乏 Tab 切换引导 | 设计统一的 UserSummary 头部，采用 Tabs 隔离发布与评价 **[P2]** |
| **消息中心 `/messages`** | 对话列表与消息内容未很好地形成响应式 Chat 布局 | 移动端和桌面端布局混淆 | 输入框与发送按钮不够精致 | 重构现代 Glassmorphism 主从 Chat 架构 **[P2]** |
| **订单中心 `/my/orders`** | 状态流转按钮大小、颜色不一致 | 订单卡片内部嵌套过多 border | 操作区按钮无主次分割 | 统一 OrderCard 结构与 StatusBadge **[P2]** |

## 3. 重构路线图

1. **第一阶段**：建立统一 Design Tokens 与基础 UI 组件库（PageContainer, PageHeader, PrimaryButton, StatusBadge, UserSummaryCard 等）。
2. **第二阶段**：重构 SiteHeader 与 MobileBottomNav 全局框架。
3. **第三阶段**：全面重构商品详情页 `/products/[id]`（Dialog/Drawer 模式购买与举报）。
4. **第四阶段**：重构四大广场列表与卡片（二手、跑腿、技能、租赁）。
5. **第五阶段**：重构发布/编辑表单规范（FormSection 组装）。
6. **第六阶段**：重构订单、消息、个人中心及认证页面。
7. **第七阶段**：响应式 Mobile 适配与系统全量验证（`npx tsc --noEmit` & `npm run build`）。
